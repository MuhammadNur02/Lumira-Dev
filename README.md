# Lumira

Premium single-vendor storefront for boilerplates, UI kits and templates: Bento Grid 2.0 catalog,
live previews, Lemon Squeezy checkout and licensing, private R2 delivery, a buyer Library, a
license-gated shadcn registry and an owner admin dashboard.

The product spec is in [PRD.md](PRD.md), the design system in [StyleGuide.md](StyleGuide.md) and
the build plan in [Task.md](Task.md). Operational procedures are in [docs/runbooks](docs/runbooks).

## Stack

| Concern | Choice |
|---|---|
| Framework | Next.js 16 App Router, Cache Components (`"use cache"` + tags), typed routes, `proxy.ts` |
| UI | React 19, Tailwind CSS v4, shadcn/ui (patched, see `src/components/ui/PATCHES.md`), Motion springs, View Transitions |
| Data | Postgres (Supabase) + Drizzle ORM, schema `app`, RLS, runtime role `lumira_app` |
| Auth | Clerk (Core 3) |
| Commerce | Lemon Squeezy (Merchant of Record, license keys) |
| Content | Sanity (Studio in `studio/`), Fumadocs for `/docs` (`content/docs`) |
| Delivery | Cloudflare R2, pre-signed URLs only |
| Email | Resend + React Email (`src/emails`), transactional outbox |
| Ops | Upstash Redis (rate limits, caches), QStash (release fan-out), PostHog, Sentry, Vercel Cron |

## Local development

Requirements: Node 24 (`.nvmrc`), pnpm, and Postgres 17 (`docker compose up -d postgres`, or any
local instance).

```bash
pnpm install
pnpm env:local        # writes .env.local with random secrets and CONTENT_SOURCE=fixtures
pnpm db:migrate       # applies src/db/migrations (schema app, RLS, lumira_app role)
pnpm db:seed          # 90 days of synthetic buyers, orders, keys and MRR (local DB only)
pnpm dev
```

With `CONTENT_SOURCE=fixtures` the storefront renders the seed catalog from
`src/lib/sanity/fixtures.ts` before a Sanity project exists. Clerk runs in keyless mode when its
keys are empty. Placeholder art is generated by `pnpm gen:fixture-art`.

To see the admin dashboard locally, sign in once, then re-run the seed with your Clerk user id and
set `publicMetadata.role = "admin"` on that user in the Clerk dashboard (and enable MFA):

```bash
SEED_ADMIN_CLERK_ID=user_xxx SEED_ADMIN_EMAIL=you@example.com pnpm db:seed
```

## Scripts

| Script | What it does |
|---|---|
| `pnpm dev` / `build` / `start` | Next.js |
| `pnpm lint` / `typecheck` / `format` | ESLint (with local Lumira rules), `tsc`, Prettier |
| `pnpm test` | Vitest: unit + integration (PGlite gives each suite a migrated in-memory Postgres) |
| `pnpm test:e2e` | Playwright + axe (`e2e/`); boots `next dev` unless `PLAYWRIGHT_BASE_URL` is set |
| `pnpm db:generate` / `db:migrate` / `db:studio` | Drizzle Kit |
| `pnpm db:seed` | Deterministic demo data; truncates schema `app`; refuses production |
| `pnpm ls:sync` | Pulls prices and activation limits from Lemon Squeezy into Sanity and Postgres |
| `pnpm typegen` | Sanity TypeGen (Studio schema → `src/sanity/types.ts`) |
| `pnpm email:dev` | React Email preview server |
| `pnpm check:contrast` / `gen:springs` | Design-token checks and spring → CSS `linear()` generation |

## Layout

```
src/app/(site)      Storefront root layout: static shells, streamed personal holes
src/app/(app)       Account, admin, checkout success, auth, email links: dynamic, CSP nonce
src/app/api         Webhooks, downloads, license proxy, registry, cron, queue, health
src/server          Domain services (server-only): commerce, licensing, delivery, outbox, admin
src/lib             Shared libraries: env, billing adapter, Sanity, R2, CSP, formatting
src/components      ui (shadcn), lumira (brand), commerce, preview, admin, docs
src/db              Drizzle schema, client and migrations
packages/           @lumira/bento (grid validator), @lumira/preview-bridge, lumira CLI
studio/             Sanity Studio
tests/ e2e/         Vitest suites and Playwright specs
```

## Security model (short)

- Authorization is checked in every page, route handler and Server Action (`requireUser`,
  `requireAdmin`); `proxy.ts` only handles sessions, cookies and CSP.
- Webhooks: signature verified on the raw body (Lemon Squeezy HMAC, Clerk/Resend Svix, Sanity),
  then recorded in an idempotent ledger; handlers are replayable from the admin inspector.
- License keys are stored AES-256-GCM encrypted with an HMAC lookup hash; they never enter logs,
  analytics or the webhook ledger.
- Downloads are pre-signed R2 URLs (60–300 s) behind entitlement checks and rate limits. Email
  links are single-purpose JWTs whose uses are consumed only by an explicit POST.
- Admin mutations are audited (`withAudit`, append-only `audit_log`); destructive ones require
  Clerk step-up reverification.
- CSP ships as report-only (`CSP_MODE=report-only`); switch to `enforce` after a clean week.
